AI 추출 스키마 지침

AI가 주문 원문에서 추출한 결과를 API, DB, Merchant 검수 화면이 동일하게 해석하도록 스키마를 정의한다.

기본 원칙

  • AI 결과는 확정 주문이 아니라 후보 데이터다.
  • 원문 rawText는 항상 보관한다.
  • 추출 결과에는 confidence와 확인 필요 사유를 함께 둔다.

공통 스키마

{
  "businessChannel": "PACKAGING_CUSTOM",
  "businessType": "PACKAGING",
  "customerCandidate": {
    "customerId": null,
    "customerNameText": "한국유통",
    "confidence": 0.72
  },
  "requestedDeliveryDate": "2026-06-20",
  "lineItems": [],
  "needsReviewReasons": [],
  "extractionConfidence": 0.81
}

확인 필요 사유

값의미
CUSTOMER_NOT_MATCHED거래처 후보를 확정하지 못함
ITEM_NOT_MATCHED내부 품목과 매칭하지 못함
PRICE_NOT_MATCHED단가를 확정하지 못함
DESIGN_FILE_REQUIRED디자인 파일 확인 필요

API 검증 기준

  • 최상위 객체 응답은 extractionConfidence가 0 이상 1 이하 숫자여야 한다.
  • lineItems는 배열이어야 한다.
  • 각 line item은 itemCandidateName 또는 itemName이 있어야 한다.
  • 품목명은 300자 이하, 수량 텍스트는 80자 이하로 제한한다.
  • requestedDueDate가 있으면 YYYY-MM-DD 형식이어야 한다.
  • confidence가 있으면 0 이상 1 이하 숫자여야 한다.
  • needsReviewReasons는 이 문서의 확인 필요 사유 값만 허용한다.

검증에 실패한 전체 응답 또는 line item은 반영하지 않는다. 반영할 후보가 없으면 기존 규칙 기반 후보를 사용한다.
