ShipMate 문서 작성 가이드라인

문서 원칙

문서 유형기준 형식
설명형 개발 문서Markdown
브라우저 보기 문서HTML
API 설명 문서Markdown + HTML
표준값/코드표 설명 문서Markdown + HTML
  • 모든 문서 원본은 .md 파일로 작성한다.
  • 브라우저에서 볼 문서는 .html 파일로 생성하거나 유지한다.
  • Markdown과 HTML 내용이 다르면 Markdown을 기준으로 한다.
  • shipmate-doc 안에서는 YAML 문서를 새로 만들지 않는다.
  • YAML은 문서 산출물이 아니며, 문서 생성 대상에서도 제외한다.

문서 위치

구분Markdown 원본HTML 보기 파일
공통common/shipmate-common/html/
Androidandroid/shipmate-android/html/
Adminadmin/shipmate-admin/html/

금지 규칙

  • 새 문서를 .yaml 또는 .yml 파일로 생성하지 않는다.
  • 새 source 문서를 root yaml/ 아래에 추가하지 않는다.
  • 도메인 문서를 root html/ 아래에 추가하지 않는다.
  • 필드명, master code, status code, error code number를 shipmate-doc/data/에 저장하지 않는다.

공통 데이터 자산

공통 데이터 자산은 Markdown 원본과 HTML 보기 파일로 관리한다.

기존 YAML 공통 데이터 자산은 제거하며, 새 기준 문서는 shipmate-doc/shipmate-common 아래에 둔다.

자산위치목적
Field namesshipmate-doc/shipmate-common/shared-field-names.md
shipmate-doc/shipmate-common/html/shared-field-names.html		공유 표준 field name
Master codesshipmate-doc/shipmate-common/master-codes.md
shipmate-doc/shipmate-common/html/master-codes.html		RDB master code table과 seed data의 향후 기준
Error codesshipmate-doc/shipmate-common/error-codes.md
shipmate-doc/shipmate-common/html/error-codes.html		표준 error message code와 code number

필드와 DB 컬럼 생성 전 확인

  • 새 API field, DTO field, Java/Kotlin/TypeScript field, 화면 데이터 field를 만들기 전에는 shipmate-doc/shipmate-common/field-dictionary.md를 먼저 확인한다.
  • 새 field가 기존 사전에 없으면 구현 전 또는 구현과 동시에 필드 딕셔너리 Markdown/HTML에 의미, DB column 연결 여부, codeSet 여부를 기록한다.
  • 새 DB table 또는 column을 만들기 전에는 shipmate-doc/shipmate-common/database-column-dictionary.md를 먼저 확인한다.
  • 새 DB column이 기존 사전에 없으면 Flyway migration 작성 전 또는 작성과 동시에 DB 컬럼 딕셔너리 Markdown/HTML에 table, column, API field, type, nullable, index/FK, code_set 여부를 기록한다.
  • API field와 DB column이 연결되는 업무 데이터는 필드 딕셔너리와 DB 컬럼 딕셔너리 양쪽에서 같은 table/column을 가리키도록 맞춘다.
