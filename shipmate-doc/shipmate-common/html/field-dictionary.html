필드 딕셔너리

목적

API JSON field, Kotlin/Java/TypeScript field, enum, 화면 개념명을 통일한다. 필드 딕셔너리는 DB 컬럼 딕셔너리와 함께 관리하며, 업무 필드는 DB column, code set, 화면 문구와 연결되어야 한다.

일반명 사용 제한

id, name, phone, address, status, type, date, amount 같은 일반명은 단독으로 사용하지 않는다. 단, 엔티티 자신의 primary key인 id와 audit field인 createdAt, updatedAt은 예외로 둔다.

금지: phone, name, address, status, type
허용: customerPhoneNumber, recipientName, deliveryAddress, reviewStatus, documentType

식별자 규칙

  • id는 엔티티 자신의 primary key로만 사용한다.
  • API 요청/응답, DTO, event payload, FK 참조, 검색 조건에서는 id 단독 사용을 금지한다.
  • 외부 참조 식별자는 반드시 {entity}Id 형식으로 작성한다.
  • userId는 사용하지 않는다.

코드 테이블 연계

필드가 선택값 또는 코드값이면 codeSet을 명시한다. codeSet은 마스터 코드 문서의 code_group과 연결한다.

API fieldDB columncodeSet관리 방식
sourceChannelsource_channelSOURCE_CHANNELmaster table
businessChannelbusiness_channelBUSINESS_CHANNELmaster table
businessTypebusiness_typeBUSINESS_TYPEmaster table
documentTypedocument_typeDOCUMENT_TYPEmaster table
reviewStatusreview_status-application enum 우선
aiJobStatusai_job_status-application enum

모든 상태값을 master table에 넣지 않는다. 운영자가 선택하거나 화면 표시, 정렬, 활성 여부 관리가 필요한 값만 master table로 관리한다.

DB 저장 테이블 연결
