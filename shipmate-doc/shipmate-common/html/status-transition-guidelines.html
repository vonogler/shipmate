상태 전이 지침

주문 원문, 주문 초안, 검수, 업무문서 생성의 상태를 통일한다.

기본 원칙

  • 시스템 로직에 강하게 묶인 상태값은 application enum으로 둔다.
  • 상태 전이는 한 방향을 기본으로 하며, 되돌림은 명시된 경우에만 허용한다.
  • AI가 만든 결과를 검수 없이 APPROVED로 만들지 않는다.

주요 상태

구분상태
InboundMessageRECEIVED, DRAFTING, DRAFTED, IGNORED, FAILED
OrderDraftCREATED, NEEDS_REVIEW, SUBMITTED, CANCELED
BusinessDocumentCREATED, CONFIRMED, EXPORTED, CANCELLED

기본 전이

InboundMessage: RECEIVED -> DRAFTING -> DRAFTED
OrderDraft: CREATED -> SUBMITTED
OrderDraft: CREATED -> NEEDS_REVIEW -> CREATED -> SUBMITTED
OrderDraft: SUBMITTED -> CREATED
BusinessDocument: CREATED -> CONFIRMED -> EXPORTED

출고표 수정 정책

  • 제출된 출고표는 직접 수정하지 않는다.
  • 제출 후 수정이 필요하면 POST /api/shipping-orders/{orderDraftId}/reopen-review로 SUBMITTED -> CREATED 재검수 전환을 수행한다.
  • 재검수 전환 요청 본문에는 reopenReason을 넣어야 하며, 입력한 사유는 변경 이력 summary와 tb_audit_logs.metadata_json에 기록한다.
  • 재검수 전환 후 이용자는 초안 검수 화면에서 배송 정보, 품목, 단가 후보, 메모를 수정하고 다시 제출한다.
  • 재검수 전환, 검수 저장, 재제출은 변경 이력에 각각 ORDER_DRAFT_REOPENED, ORDER_DRAFT_REVIEW_UPDATED, ORDER_DRAFT_SUBMITTED로 기록한다.
  • 택배 CSV 생성과 검증은 SUBMITTED 상태의 출고표만 대상으로 한다.
