# 포장재/판촉물/맞춤 제작 소모품 채널

## 목적

출고비서의 초기 영업과 제품 뼈대를 `포장재/판촉물/맞춤 제작 소모품` 채널로 따로 기록한다.

결론은 외부 영업과 초기 화면은 한 가지 업종에 집중하고, 내부 데이터 구조는 세 가지 업종을 확장 가능하게 둔다.

```text
영업/화면/샘플: 포장재 주문제작에 집중
데이터 모델/문서 타입: 포장재, 판촉물, 맞춤 제작 소모품을 확장 가능하게 설계
```

## 집중 타깃

초기 집중 타깃은 `포장재 주문제작`이다.

대상 예시:

- 박스
- 쇼핑백
- 스티커
- 라벨
- 포장용 봉투
- 소량 패키지 제작

초기 영업 문구:

```text
카톡으로 받은 포장재 주문을
견적 후보, 작업지시서, 출고표로 정리합니다.
```

## 왜 한 가지에 집중하는가

포장재, 판촉물, 맞춤 제작 소모품은 비슷하지만 영업 메시지가 다르다.

| 구분 | 고객이 기대하는 핵심 |
|---|---|
| 포장재 | 박스, 쇼핑백, 라벨, 스티커, 포장 사양, 인쇄 파일 |
| 판촉물 | 행사명, 로고, 인쇄 위치, 납기, 수량, 품목 옵션 |
| 맞춤 제작 소모품 | 규격, 재질, 반복 주문, 작업 조건 |

처음부터 “세 가지를 모두 지원한다”고 말하면 메시지가 흐려진다. 반대로 “포장재 카톡 주문을 작업지시서와 출고표로 정리한다”고 말하면 고객이 바로 이해하기 쉽다.

## 왜 포장재 주문제작인가

- 참고 모델이 명확하다.
- 박스, 쇼핑백, 스티커, 라벨까지 확장 가능하다.
- “지난번 주문”, “로고 변경”, “수량 변경”, “디자인 파일 검수” 같은 출고비서 핵심 기능이 잘 드러난다.
- 판촉물보다 상품 범위가 덜 넓다.
- 금속/의약품보다 규제와 견적 난이도가 낮다.

참고 사이트:

- [패커티브](https://packative.com/): 커스텀 패키지, 종이박스, 골판지박스, 쇼핑백 제작
- [레드프린팅](https://www.redprinting.co.kr/ko): 명함, 홍보물, 스티커, 판촉물, 포장자재, 인쇄물 제작

## 공통 업무 흐름

```text
카카오톡/문자/이메일 주문 원문
-> 주문 또는 견적 후보 추출
-> 이용자 검수
-> 작업지시서 생성
-> 출고표/납품서/택배 CSV 생성
```

## 초기 화면 기준

초기 화면은 포장재 기준으로 만든다.

필수 입력/추출 필드:

| 필드 | 설명 |
|---|---|
| 품목 | 박스, 쇼핑백, 스티커, 라벨 |
| 규격 | 가로, 세로, 높이 또는 지름 |
| 재질 | 종이, 골판지, 비닐, 기타 |
| 수량 | 제작 수량 |
| 인쇄 여부 | 무지, 단색, 컬러, 별도 확인 |
| 디자인 파일 | 새 파일, 기존 파일 재사용, 파일 필요 |
| 지난 주문 참조 | 지난번과 동일, 지난 주문 일부 변경 |
| 납기 | 희망 제작 완료일 또는 배송일 |
| 배송지 | 납품 또는 택배 주소 |
| 메모 | 후가공, 포장, 주의사항 |

주문 원문 예시:

```text
지난번 쇼핑백 1,000장 다시 주세요.
로고만 새 파일로 바꿔서 진행 부탁합니다.
다음 주 금요일까지 받을 수 있을까요?
```

## 내부 확장 구조

외부 영업은 포장재에 집중하지만 내부 구조는 세 가지 채널을 막지 않는다.

```text
sourceChannel
- KAKAO_PASTE
- SMS_SHARE
- EMAIL
- ORDER_PAGE

businessChannel
- PACKAGING_CUSTOM
- BEAUTY_SUPPLIES
- MRO_SUPPLIES
- APPAREL_WHOLESALE
- METAL_MATERIALS
- PHARMACY_SUPPLIES

BusinessType
- PACKAGING
- PROMOTIONAL_GOODS
- CUSTOM_SUPPLIES

DocumentType
- ORDER_DRAFT
- QUOTE_REQUEST
- WORK_ORDER
- SHIPMENT_SHEET
- DELIVERY_NOTE
- SHIPPING_CSV
```

## 프로젝트 구성 결정

현재 단계에서는 업종별 프로젝트를 새로 만들지 않고 `shipmate-merchant` 안에서 업종 템플릿으로 나눈다.

```text
shipmate-merchant
  공통 기능
    주문함
    주문 초안
    검수
    업무문서
    거래처
    품목
    단가
  업종 템플릿
    포장재/판촉물/맞춤 제작
    미용재료/화장품 도매
    공구/MRO 소모품
    의류/패션 도매
    금속/자재 견적
    약국 소모품
```

이유:

- 핵심 흐름은 업종별로 완전히 다르지 않다.
- 주문 원문 수집, AI 후보 추출, 이용자 검수, 업무문서 생성, 택배 CSV/납품서 출력은 공통이다.
- 업종별 차이는 주로 추출 필드, 검수 화면 템플릿, 문서 템플릿이다.
- 시장 검증 전 프로젝트를 나누면 로그인, 권한, 거래처, 주문 초안, 검수 화면을 중복 구현하게 된다.

초기 구현은 `PACKAGING_CUSTOM`만 실제 화면까지 만든다. 다른 업종은 `businessChannel` 구조에서 확장 가능하게만 둔다.

프로젝트 분리는 다음 조건이 생겼을 때 검토한다.

- 업종별 로그인/권한이 완전히 달라진다.
- 요금제가 완전히 달라진다.
- 화면 흐름이 70% 이상 달라진다.
- 운영팀이나 배포 주기가 달라진다.
- 법적/규제 요건이 독립적으로 커진다.
- 고객에게 별도 브랜드로 팔아야 한다.

## 개발 순서

1. `shipmate-api`에 주문 원문과 주문 초안의 공통 저장 구조를 만든다.
2. `sourceChannel`과 `businessChannel`을 분리해 저장한다.
3. 첫 `businessChannel`은 `PACKAGING_CUSTOM`으로 둔다.
4. `shipmate-merchant`에 주문 원문 목록과 주문 초안 목록을 만든다.
5. 포장재 주문제작 기준 검수 화면을 만든다.
6. AI 없이도 원문을 수동으로 주문/견적 후보로 저장할 수 있게 한다.
7. AI 주문 후보 추출을 붙인다.
8. 작업지시서 초안을 만든다.
9. 출고표/납품서 초안을 만든다.
10. 승인 주문 기준 택배 CSV 다운로드를 만든다.
11. 지난 주문 참조와 반복 주문 불러오기를 붙인다.
12. 이후 `PROMOTIONAL_GOODS`, `CUSTOM_SUPPLIES` 필드를 확장한다.

## 판촉물 확장 필드

판촉물로 확장할 때 추가될 수 있는 필드:

- 행사명
- 로고 인쇄 위치
- 인쇄 색상
- 개별 포장 여부
- 증정/납품 장소
- 행사일

## 맞춤 제작 소모품 확장 필드

맞춤 제작 소모품으로 확장할 때 추가될 수 있는 필드:

- 규격
- 재질
- 가공 조건
- 반복 주문 여부
- 샘플 필요 여부
- 작업 조건

## 만들지 않을 것

초기에는 다음 범위를 만들지 않는다.

- 세 업종 전체를 한 화면에서 모두 설명하는 범용 랜딩
- 자동 카카오톡 수집
- 복잡한 ERP 연동
- 완전 자동 승인
- 금속 견적 자동화
- 전문의약품 기능

## 결론

초기 제품과 영업은 `포장재 주문제작`에 집중한다.

다만 내부 모델은 `포장재/판촉물/맞춤 제작 소모품` 채널로 묶어, 나중에 판촉물과 맞춤 제작 소모품으로 자연스럽게 확장할 수 있게 설계한다.
